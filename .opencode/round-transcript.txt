## 3. Core engine contracts

### `digart/engine/image_state.py`

Maintain the working image and a limited undo history.

- `class ImageState`
  - `source: Image.Image` — original RGB image.
  - `current: Image.Image` — image currently shown (preview-resolution or full-resolution depending on caller).
  - `history: collections.deque[Image.Image]` with `maxlen=10`.
  - `push(image) -> None` — set `current`, push previous `current` to `history`.
  - `reset() -> None` — restore `current = source`, clear `history`.
  - `undo() -> bool` — pop history and restore; return `True` if something was undone.

All internal images are `mode="RGB"` (drop alpha on load).

## 5. Databending engine

File: `digart/engine/databend.py`.

### Design goals

- Operate on **real file bytes**, not pixel buffers.
- Support PNG and JPEG-specific corruption patterns.
- Degrade gracefully: a failed decode must return the input image and a warning, not crash.
- Deterministic via `rng`.

### Core utilities

```python
def corrupt_bytes_bitflip(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_drop(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_duplicate(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_shuffle_chunks(data: bytes, chunk_size: int, shuffle_amount: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_png_idat(data: bytes, intensity: float, rng: np.random.Generator) -> bytes
def corrupt_jpeg_body(data: bytes, intensity: float, rng: np.random.Generator) -> bytes
```

### Header-protection rules

For **all** generic byte corruptions, when `protect_headers=True`:

- PNG: never touch the first 8 signature bytes or the `IHDR` chunk.
- JPEG: never touch the first 2 bytes (`FF D8`) or the last 2 bytes (`FF D9`). Avoid bytes that are part of a marker prefix (`0xFF` followed by a non-`0x00` byte) and the byte immediately following any `0xFF` marker.
- Generic fallback: protect the first 32 and last 4 bytes.

### Decode-and-recover

```python
def decode_bent_bytes(data: bytes) -> Image.Image | None
```

Try `Image.open(BytesIO(data)).load()`. If it succeeds, convert to RGB and return. If it fails, try progressively safer fallbacks:

1. If a PNG and a chunk-level corruption was applied, try to repair only the CRC.
2. Reduce the last corruption intensity by half and retry (up to 3 times).
3. Return `None` so the caller can fall back to the pre-databend image.

### Databend effects exposed to the pipeline

In `digart/effects/glitch.py` (or a separate `databend_effects.py`), implement:

| Effect | ID | Parameters (default) | Behavior |
|---|---|---|---|
| **Bit Flip** | `databend_bitflip` | `intensity` float (0.0..0.1, 0.005), `protect_headers` bool (True) | `corrupt_bytes_bitflip` on current image saved as PNG bytes, then decode. |
| **Byte Drop** | `databend_drop` | `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True) | `corrupt_bytes_drop` on PNG bytes, then decode. |
| **Byte Duplicate** | `databend_duplicate` | `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True) | `corrupt_bytes_duplicate` on PNG bytes, then decode. |
| **Chunk Shuffle** | `databend_shuffle` | `chunk_size` int (2..256, 16), `shuffle_amount` float (0.0..1.0, 0.1), `protect_headers` bool (True) | `corrupt_bytes_shuffle_chunks` on PNG bytes, then decode. |
| **PNG IDAT Corrupt** | `databend_png_idat` | `intensity` float (0.0..0.05, 0.005) | `corrupt_png_idat`. |
| **JPEG Body Corrupt** | `databend_jpeg_body` | `intensity` float (0.0..0.05, 0.005) | Re-encode current image to JPEG (quality 95) into bytes, then `corrupt_jpeg_body`. |

Each effect returns the pre-databend image if decoding fails, and appends a warning string.

### Safety contract

Running any databend effect on **any** file type must never crash the app. At worst it produces no visible change and a status-bar warning.

```python
    parser.add_argument("--width", type=int, default=800, help="Default generated image width")
    parser.add_argument("--height", type=int, default=600, help="Default generated image height")
    return parser.parse_args()

def main():
    args = parse_args()
    app = create_app()
    state = ImageState()
    # If args.image provided and exists, load it as RGB into state.source/state.current.
    window = MainWindow(state=state, initial_seed=args.seed, default_width=args.width, default_height=args.height)
    if args.image and Path(args.image).is_file():
        window.load_image(Path(args.image))
    window.show()
    sys.exit(app.exec())

if __name__ == "__main__":
    main()
```

## 3. Core engine contracts

### `digart/engine/image_state.py`

Maintain the working image and a limited undo history.

- `class ImageState`
  - `source: Image.Image` — original RGB image.
  - `current: Image.Image` — image currently shown (preview-resolution or full-resolution depending on caller).
  - `history: collections.deque[Image.Image]` with `maxlen=10`.
  - `push(image) -> None` — set `current`, push previous `current` to `history`.
  - `reset() -> None` — restore `current = source`, clear `history`.
  - `undo() -> bool` — pop history and restore; return `True` if something was undone.

All internal images are `mode="RGB"` (drop alpha on load).

### `digart/effects/base.py`

```python
@dataclass
```

The `params` dict passed to `apply` contains the current value for every `ParamDef` keyed by `name`.

### `digart/effects/glitch.py` — algorithmic glitch effects

Implement the following five effects as subclasses of `Effect`. All operate at the pixel/RGB level and return a new `Image.Image`.

| Effect | ID | Parameters (default) | Behavior |
|---|---|---|---|
| **Channel Shift** | `channel_shift` | `red_offset` int (-20..20, 0), `green_offset` int (-20..20, 0), `blue_offset` int (-20..20, 0), `vertical` bool (False) | Split RGB channels. Convert to numpy H×W×3. For each channel, `np.roll` horizontally by its offset (vertical roll if `vertical=True`). Clip and reconstruct. |
| **Scanline Tear** | `scanline_tear` | `tears` int (0..50, 10), `max_shift` int (0..100, 20), `thickness` int (1..20, 2) | Randomly pick `tears` horizontal row ranges of height `thickness`; shift each slice horizontally by a random amount in `[-max_shift, max_shift]`. |
| **Pixel Sort** | `pixel_sort` | `threshold` int (0..255, 128), `angle` choice {`horizontal`,`vertical`}, `sort_by` choice {`lightness`,`hue`,`saturation`} | For each row (or column), find contiguous runs where the sort metric exceeds `threshold`, then sort pixels inside each run by that metric. |
| **Block Displacement** | `block_displace` | `block_size` int (8..128, 32), `count` int (0..50, 10), `max_shift` int (0..100, 30), `mode` choice {`copy`,`move`} | Randomly select `count` axis-aligned blocks of size `block_size`. Copy or move them to a nearby random offset, wrapping around edges. |
| **Glitch Slice** | `glitch_slice` | `slices` int (2..100, 12), `max_shift` int (0..80, 20), `direction` choice {`horizontal`,`vertical`} | Divide the image into `slices` strips; shift every strip by a random offset in `[-max_shift, max_shift]`, wrapping around edges. |

### `digart/effects/noise.py`

Implement four noise effects. Each must support `per_channel` (bool). When `per_channel=True`, generate independent noise for R/G/B. When `per_channel=False`, generate single-channel luminance noise and add equally to all channels.

| Effect | ID | Parameters (default) | Behavior |
|---|---|---|---|
| **Gaussian Noise** | `gaussian_noise` | `sigma` float (0..100, 10), `per_channel` bool (True), `seed` int (0) | Generate Gaussian noise N(0, sigma²), add to image, clip 0-255. Use `skimage.util.random_noise(..., mode='gaussian', var=(sigma/255)²)` or a numpy equivalent. |
| **Salt & Pepper** | `salt_pepper` | `amount` float (0.0..0.5, 0.05), `salt_ratio` float (0.0..1.0, 0.5), `per_channel` bool (True), `seed` int (0) | Randomly set pixels to 0 or 255. Use `skimage.util.random_noise(..., mode='s&p')` when `per_channel=False`; implement per-channel manually when `per_channel=True`. |
| **Value Noise** | `value_noise` | `scale` int (1..100, 20), `octaves` int (1..8, 3), `persistence` float (0.0..1.0, 0.5), `per_channel` bool (True), `seed` int (0) | Generate multi-octave value noise on a grid, interpolate to image size (e.g. `scipy.ndimage.zoom`), scale to `[0,255]`, blend with image using `intensity` or add. |
| **Film Grain** | `film_grain` | `intensity` float (0..100, 15), `grain_size` int (1..10, 2), `monochrome` bool (False), `seed` int (0) | Generate small high-frequency noise texture, blur it slightly (`grain_size`), scale by `intensity`, add to image. When `monochrome=True`, use single-channel noise; else per-channel. |

All noise effects use `rng` for deterministic output. `seed` in the params is ignored in favor of the `rng` passed by the pipeline (which is already seeded from the global seed and the effect ID).

## 5. Databending engine

File: `digart/engine/databend.py`.

### Design goals

- Operate on **real file bytes**, not pixel buffers.
- Support PNG and JPEG-specific corruption patterns.
- Degrade gracefully: a failed decode must return the input image and a warning, not crash.
- Deterministic via `rng`.

### Core utilities

```python
def corrupt_bytes_bitflip(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_drop(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_duplicate(data: bytes, intensity: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_bytes_shuffle_chunks(data: bytes, chunk_size: int, shuffle_amount: float, protect_headers: bool, rng: np.random.Generator) -> bytes
def corrupt_png_idat(data: bytes, intensity: float, rng: np.random.Generator) -> bytes
def corrupt_jpeg_body(data: bytes, intensity: float, rng: np.random.Generator) -> bytes
```

### Header-protection rules

For **all** generic byte corruptions, when `protect_headers=True`:

- PNG: never touch the first 8 signature bytes or the `IHDR` chunk.
- JPEG: never touch the first 2 bytes (`FF D8`) or the last 2 bytes (`FF D9`). Avoid bytes that are part of a marker prefix (`0xFF` followed by a non-`0x00` byte) and the byte immediately following any `0xFF` marker.
- Generic fallback: protect the first 32 and last 4 bytes.

### Decode-and-recover

```python
def decode_bent_bytes(data: bytes) -> Image.Image | None
```

Try `Image.open(BytesIO(data)).load()`. If it succeeds, convert to RGB and return. If it fails, try progressively safer fallbacks:

1. If a PNG and a chunk-level corruption was applied, try to repair only the CRC.
2. Reduce the last corruption intensity by half and retry (up to 3 times).
3. Return `None` so the caller can fall back to the pre-databend image.

### Databend effects exposed to the pipeline

In `digart/effects/glitch.py` (or a separate `databend_effects.py`), implement:

| Effect | ID | Parameters (default) | Behavior |
|---|---|---|---|
| **Bit Flip** | `databend_bitflip` | `intensity` float (0.0..0.1, 0.005), `protect_headers` bool (True) | `corrupt_bytes_bitflip` on current image saved as PNG bytes, then decode. |
| **Byte Drop** | `databend_drop` | `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True) | `corrupt_bytes_drop` on PNG bytes, then decode. |
| **Byte Duplicate** | `databend_duplicate` | `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True) | `corrupt_bytes_duplicate` on PNG bytes, then decode. |
| **Chunk Shuffle** | `databend_shuffle` | `chunk_size` int (2..256, 16), `shuffle_amount` float (0.0..1.0, 0.1), `protect_headers` bool (True) | `corrupt_bytes_shuffle_chunks` on PNG bytes, then decode. |
| **PNG IDAT Corrupt** | `databend_png_idat` | `intensity` float (0.0..0.05, 0.005) | `corrupt_png_idat`. |
| **JPEG Body Corrupt** | `databend_jpeg_body` | `intensity` float (0.0..0.05, 0.005) | Re-encode current image to JPEG (quality 95) into bytes, then `corrupt_jpeg_body`. |

Each effect returns the pre-databend image if decoding fails, and appends a warning string.

### Safety contract

Running any databend effect on **any** file type must never crash the app. At worst it produces no visible change and a status-bar warning.

## 1. Blockers

### B1 — Effects are not reproducible across process launches: `hash()` on a string salt
`digart/utils/rng.py:16`
```python
effective = hash((seed, salt)) & 0xFFFFFFFF
```
`salt` is always `effect.id` — a *string* (`"channel_shift"`, `"salt_pepper"`, `"databend_bitflip"`, …), passed from `pipeline.py:72` as `get_rng(global_seed, salt=effect.id)`.

Python's builtin `hash()` of a `str` is salted with a per-process random seed (`PYTHONHASHSEED`), so `hash((42, "channel_shift"))` returns a different value on every app launch. The resulting `np.random.default_rng(effective)` therefore produces a different generator every run.

This violates spec rule 3 ("same global seed + same params → identical output") and the README's "Deterministic output via a single global seed" claim. Within a single run, preview and export are consistent (same process hash), but launch the app twice with `--seed 42` and the same settings and you get different art. This is exactly the "embarrass the crew" failure: a user who saves a seed expecting to reproduce an image cannot.

(The fix would be a stable digest, e.g. `int.from_bytes(hashlib.blake2b(f"{seed}:{salt}".encode(), digest_size=4).digest(), "big")` or `zlib.crc32(f"{seed}:{salt}".encode())` — not applying it here.)

## 2. Warnings

### W2 — Monochrome Salt & Pepper corrupts entire rows, not pixels
`digart/effects/noise.py:70-71`
```python
arr[ys[salt_mask], :] = 255
arr[ys[~salt_mask], :] = 0
```
In the `per_channel=False` branch the code indexes `arr[ys[...], :]` — all columns — instead of `arr[ys[...], xs[...], :]`. Because `ys` is the row index of the selected pixels (and rows repeat, since `rng.choice(total, replace=False)` selects distinct *pixel* indices that share rows), the monochrome mode paints full-width horizontal white/black stripes rather than salt-and-pepper dots. The per-channel branch (line 60-65) is correct; only the monochrome path is broken. Visually wrong but not fatal.

### W3 — The "debounce" is a delay, not a debounce
`digart/gui/main_window.py:276-280`
```python
def _schedule_preview(self):
    if not self._live_preview or not self.state.has_image:
        return
    QTimer.singleShot(120, self._run_preview)
```
Every parameter-change event schedules a *new* one-shot `singleShot`; none are cancelled or coalesced. Dragging a slider fires dozens of `valueChanged` events → dozens of `_run_preview` calls → a queue of preview workers (pool is capped at 1 thread, so they run serially). The 120 ms is a *delay*, not a debounce. Combined with W4 (full-res preview), this produces visible stutter and wasted CPU on large images. The stale-result discard in `_on_preview_finished` (line 300-303) is correct but never actually exercised, because serial execution guarantees results arrive in counter order.

### W4 — Preview applies effects at full resolution, then downscales (spec deviation + perf)
`digart/engine/pipeline.py:68-81` (and `worker.py:40-46`)
The pipeline applies every effect to `source` at full resolution and only downsizes *afterwards* via `make_preview`. Spec rule 5 says "Preview runs on a preview-scaled copy." For a large source this runs `PixelSort` (a per-row Python loop), `SaltPepper`, and the entire PNG/JPEG encode→corrupt→decode databend cycle at full resolution — the exact work a preview scale was meant to avoid. (There is a genuine tension here: downscaling first would make dimension-dependent effects diverge between preview and export, which is presumably why it was written this way — but as delivered it does not match the spec and makes "live" preview slow for big sources.)

### W5 — QRunnable and its signals QObject are not kept alive
`digart/gui/worker.py:16-36`, `digart/gui/main_window.py:288-298`
`PreviewWorker` creates `self.signals = PreviewWorkerSignals()` and the whole `worker` object is a local variable in `_run_preview`; nothing retains a reference after the method returns. This is the classic PySide6 `QThreadPool` + `QRunnable` lifetime pitfall: the Python wrapper (and its `signals` QObject) can be garbage-collected while the task is still queued or running, which manifests as either a dropped `finished` signal (preview silently never updates) or a `RuntimeError: Internal C++ object already deleted` / hard crash. The risk is amplified by W3, which floods the pool with queued workers whose wrappers outlive the scheduling frame. I could not execute the app to reproduce the race; flagged on the strength of the known pattern. The standard mitigation is to retain the runnables (e.g., a list on `MainWindow`) or use `setAutoDelete(False)` with explicit cleanup.

### W6 — Export runs synchronously on the GUI thread
`digart/gui/main_window.py:451-457`
`_export` calls `apply_pipeline(..., preview=False)` directly on the main thread with no progress indicator. For a large image or a slow databend this freezes the UI for seconds (no re-entrancy, no "Processing…", no `QProgressDialog`). Not a crash, but a poor experience on exactly the operation users care most about. This is also where a slow worker (W5/W7) is most likely to be running concurrently.

### W7 — `closeEvent` only waits 500 ms for the worker pool
`digart/gui/main_window.py:467-469`
`self._thread_pool.waitForDone(500)` then `event.accept()`. A databend at full resolution can easily exceed 500 ms; the app will then tear down while a worker thread is still running, which can emit Qt's "QThreadPool destroyed while thread is running" and crash on exit.

## Effects (implement as Effect subclasses; operate at pixel/RGB level; deterministic via rng)

### Algorithmic glitch — `digart/effects/glitch.py`
1. **channel_shift** — `red_offset`/`green_offset`/`blue_offset` int (-20..20, 0), `vertical` bool (False). np.roll each channel by its offset (horizontal, or vertical if vertical=True), reconstruct.
2. **scanline_tear** — `tears` int (0..50, 10), `max_shift` int (0..100, 20), `thickness` int (1..20, 2). Random horizontal row slices of given thickness shifted horizontally.
3. **pixel_sort** — `threshold` int (0..255, 128), `angle` choice {horizontal,vertical}, `sort_by` choice {lightness,hue,saturation}. Sort contiguous runs above threshold.
4. **block_displace** — `block_size` int (8..128, 32), `count` int (0..50, 10), `max_shift` int (0..100, 30), `mode` choice {copy,move}. Random axis-aligned blocks copied/moved to nearby random offset, wrapping edges.
5. **glitch_slice** — `slices` int (2..100, 12), `max_shift` int (0..80, 20), `direction` choice {horizontal,vertical}. Divide into strips and shift each.

### Noise — `digart/effects/noise.py` (all support `per_channel` bool; per_channel=True → independent R/G/B noise; False → single-channel luminance noise added equally)
1. **gaussian_noise** — `sigma` float (0..100, 10), `per_channel` bool (True). Add N(0,sigma²), clip 0-255.
2. **salt_pepper** — `amount` float (0.0..0.5, 0.05), `salt_ratio` float (0.0..1.0, 0.5), `per_channel` bool (True).
3. **value_noise** — `scale` int (1..100, 20), `octaves` int (1..8, 3), `persistence` float (0.0..1.0, 0.5), `per_channel` bool (True). Multi-octave value noise interpolated to image size (e.g. scipy.ndimage.zoom), blended/added.
4. **film_grain** — `intensity` float (0..100, 15), `grain_size` int (1..10, 2), `monochrome` bool (False). High-frequency noise blurred slightly, added.

### Byte-level databending — `digart/engine/databend.py` + six effect classes
Utility functions:
- `corrupt_bytes_bitflip(data, intensity, protect_headers, rng)`
- `corrupt_bytes_drop(data, intensity, protect_headers, rng)`
- `corrupt_bytes_duplicate(data, intensity, protect_headers, rng)`
- `corrupt_bytes_shuffle_chunks(data, chunk_size, shuffle_amount, protect_headers, rng)`
- `corrupt_png_idat(data, intensity, rng)`
- `corrupt_jpeg_body(data, intensity, rng)`
- `decode_bent_bytes(data) -> Image | None` — `Image.open(BytesIO(data)).load()`; on failure progressively reduce intensity/repair up to 3 tries; return None on failure.

Header protection (when protect_headers=True): PNG never touch first 8 signature bytes or IHDR chunk; JPEG never touch first 2 (`FF D8`) or last 2 (`FF D9`) bytes and avoid marker bytes (`0xFF` followed by non-`0x00`); generic fallback protect first 32 + last 4 bytes.

Six databend effect classes (register under `DATABEND_EFFECTS`):
1. **databend_bitflip** — `intensity` float (0.0..0.1, 0.005), `protect_headers` bool (True). Save current image as PNG bytes → corrupt → decode.
2. **databend_drop** — `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True).
3. **databend_duplicate** — `intensity` float (0.0..0.05, 0.002), `protect_headers` bool (True).
4. **databend_shuffle** — `chunk_size` int (2..256, 16), `shuffle_amount` float (0.0..1.0, 0.1), `protect_headers` bool (True).
5. **databend_png_idat** — `intensity` float (0.0..0.05, 0.005).
6. **databend_jpeg_body** — `intensity` float (0.0..0.05, 0.005). Re-encode to JPEG (quality 95) then corrupt body.

Every databend effect returns the pre-databend image if decode fails, and appends a warning string. Running on ANY file type must never crash.

## Fixes (precise, in priority order)

1. **B1 — BLOCKER: determinism broken.** In `digart/utils/rng.py`, you used `hash((seed, salt)) & 0xFFFFFFFF`. Python's `str` hash is salted per-process (PYTHONHASHSEED), so the same `--seed` produces different art on every launch. Replace with a STABLE digest, e.g. `zlib.crc32(f"{seed}:{salt}".encode("utf-8"))` (import zlib), or `int.from_bytes(hashlib.blake2b(f"{seed}:{salt}".encode(), digest_size=4).digest(), "big")`. Result must be identical across separate process launches.

2. **W2 — monochrome Salt & Pepper draws stripes.** In `digart/effects/noise.py` (~line 70), the `per_channel=False` branch indexes `arr[ys[salt_mask], :] = 255` / `arr[ys[~salt_mask], :] = 0` — painting whole rows. Fix to index both coordinates: `arr[ys[salt_mask], xs[salt_mask]] = 255` and `arr[ys[~salt_mask], xs[~salt_mask]] = 0` (mirror the correct per-channel branch, but applied to all three channels for monochrome). It must produce dots, not stripes.

3. **W5 — QRunnable/worker GC crash risk.** In `digart/gui/worker.py` + `digart/gui/main_window.py`, `PreviewWorker` (and its signals QObject) are local variables with no retained reference — classic QThreadPool lifetime bug that can drop the `finished` signal or crash. Retain a reference to each submitted runnable (e.g. keep a list `self._active_workers` on MainWindow, prune on `finished`), and/or use `setAutoDelete(False)` with explicit cleanup.

4. **N8 — BlockDisplace "move" is a no-op.** In `digart/effects/glitch.py`, `mode == "move"` writes the block back onto its own source region (identical to "copy"). Make "move" actually blank/clear the source region (e.g. set it to a neutral value) before/after placing the block, so the two modes differ meaningfully.

5. **N9 — shuffle corrupts even at 0.** In `digart/engine/databend.py` `corrupt_bytes_shuffle_chunks`, `num_swaps = max(1, ...)` forces at least one swap. When `shuffle_amount <= 0`, return `data` unchanged.

6. **N10 — "fit %" always reads 100%.** In `digart/gui/main_window.py`, the fit/zoom percentage compares an image size to itself. Compute it correctly against the actually displayed/scaled size (or remove the misleading readout if it can't be made accurate).

7. **W3 — debounce is a delay, not a debounce.** In `digart/gui/main_window.py`, `_schedule_preview` fires `QTimer.singleShot(120, ...)` per event (no cancellation). Use a single restartable `QTimer` (stop + start(120)) so rapid changes coalesce into one preview.
